Cram

Everything on the Web Technologies paper that can only be memorised — names, numbers, shapes, rules. Tick the toggle to hide the answers and say them out loud; tap a bar to peek.

The other half of the paper (reading code, finding errors) cannot be crammed — it has to be practised on paper. This page is only the part where memorising actually works.

Use it on the bus: read the left column, say the right one, tap to check.

3 · The shape of each language — recognise a line at a glance

HTML<tag>…</tag> — angle brackets; words like href src alt class id
CSSselector { property: value; } — braces and semicolons; words like color margin display font-size
JavaScriptstatements with let const function document =>
HTML comment<!-- … --> — HTML only
CSS comment/* … */ — works in CSS and JavaScript
JavaScript comment// … — JavaScript only; in CSS it breaks the next rule
file endings.html .css .js
CSS inside a page<style>…</style> or style="…"
JS inside a page<script>…</script>
loading a file<link rel="stylesheet" href="style.css"> · <script src="nav.js"></script> — both lines are HTML
the rule for naming a lineName the language of the line, not of what sits inside its quotes: document.querySelector('.quote') is JavaScript

4 · Tag pairs and roles — one word each

<ul>unordered list — order does not matter
<ol>ordered list — the order is the information (steps)
<dl> / <dt> / <dd>description list / term / description — pairs, like a glossary
<strong>important — a screen reader can stress it
<b>just bold — no meaning
<em>emphasis — changes how it is said
<i>just italic — no meaning
<head>about the page — invisible, holds title, charset, viewport, favicon, stylesheet
<header>the top of the page — visible, inside <body>
the four parts of a pageheader · nav · main · footer — only main changes page to page
<section> / <article> / <aside>a themed block / something that stands on its own / a sidebar
herothe first screen of the home page
<th> vs <td>header cell / data cell — th is what a screen reader pairs each number with
<label for="…">ties a written label to an input — click the word, the field focuses
altwhat the picture shows, said to someone who cannot see it
<html lang="en">the language of the page — decides pronunciation, translation offer, search language

6 · Names and paths — the three rules and the five mistakes

naming rulesall lowercase · spaces become hyphens · index.html is the front page of a folder
separatorforward slash / — never a backslash \
never writea path on your own disk: C:\Users\…
missing schemewww.example.com/x.png is read as a folder inside your own site — it needs https://
a space in a filenamebecomes %20; the validator rejects it
capitalsignored on Windows and macOS · a 404 on the Linux server
relative pathsimages/hero.webp · ../images/hero.webp (up one) · #prices (this page)
other schemesmailto: email · tel: phone
the four parts of an addressscheme · host · path · query — plus the fragment, which the server never sees

7 · Git words — seven nouns, three verbs

repositorythe folder whose history Git records
commita snapshot with a message
stage / indexthe changes chosen for the next commit
remote / originthe copy elsewhere / the default name for it
mainthe default branch name
clone / pull / pushcopy the whole thing / bring changes down / send commits up
git statuswhat is changed, staged, untracked
.gitignorethe list of what must never be committed
the orderadd (choose) → commit (record) → push (send) — only push needs the internet
Git vs GitHuba program on your machine, works offline · a website holding a copy. Git without GitHub: yes. The other way round: no.
how many repositoriesone per project — never one around all of them

8 · Names of errors — the words to write in Part D

HTMLunclosed tag · unclosed quote · wrong nesting (crossed) · missing alt · broken path · list item outside a list · heading level skipped · missing viewport
CSSmisspelled property (colour) · wrong comment syntax (<!-- --> or //) · selector matches nothing (capital letter) · missing ; · missing } · value with a comma (1rem, 2rem) · unit missing or spaced (32 px)
the symptom ruleCSS never reports an error — a broken declaration is simply silently dropped. That is why you check line by line.
which layertags visible or text misplaced → HTML · everything unstyled → the <link> · one rule ignored → that rule · nothing happens on click → JavaScript, open the Console · nav and footer gone → opened with file:// · image missing → the path

9 · The one-sentence answers — say each without stopping

client / serverThe browser asks, the server answers; it remembers nothing between requests.
DNSTurns a name into an IP address, so a request can be sent at all.
why standardsOne page works in every browser, because they agree to read the same code.
why separate the threeOne CSS file restyles every page · a screen reader reads HTML and ignores paint · you know which file to open · CSS is cached once.
progressive enhancementIt works, then it looks right, then it feels good.
the four stages of a page loadDNS → connect → request and response → parse, then ask again for CSS and images.
why index.htmlA server hands the front page of a folder without being told which file.
